# 003 — 殖民者狀態

## Spec

### 這個 feature 要解決什麼

002 的殖民者只會走路、接指派，本 feature 新增**七條需求、隨時間變化**：需求隨時間下降，低到門檻就自己走去補給點，若被中斷、排隊太久導致來不及補給並低到門檻則會失能，心理惡化也會造成失能，失能再生理惡化就死亡，失能時不移動、不接新指派。需求補回先只有佔位用的「補給點」（走到那格、待一下），真正的工作（建造與自動化）留給之後的 feature 接。

玩家感受到的：原本殖民者像是玩家的機器人，給什麼指令做什麼，但新增需求後殖民者更像是真實的人類，有需求需要維持。

### 需求

| # | 需求 | 來源 |
| --- | --- | --- |
| R1 | 每個殖民者有七條需求，各自是 0–100 的獨立數值：生理 `Hunger`、`Thirst`、`BodyTemp`、`Relief`、`Stamina`，心理 `Stress`、`Mood`。`Stress` 越高越糟，其餘越高越好；新殖民者都在最好的一端 | `SYSTEM.md` §2、S3；訪談 Q2；Q1 |
| R2 | 需求隨遊戲時間變化，暫停時不變、倍速時照比例。從最好到最差：`Thirst` 1 天、`Hunger` 1.5 天、`Relief` 1 天；`BodyTemp` 不變 | `SYSTEM.md` `Day`、SC7；Q2 |
| R3 | `Stamina` 手上有工作（玩家指派、建造或補給工作，含在食物補給站、水補給站、廁所待著）時下降，1 天降完全程；在休息區休息與沒有工作（閒晃、失能）時不變。只有在休息區待滿才回到 100（R7） | I4；組內 2026-11-11（Owner 修改） |
| R4 | `Mood` 在任一條生理需求低於 30 時下降、否則回升；`Stress` 手上有工作（玩家指派、建造、補給；在休息區休息不算）時上升、否則下降；各 1 天走完全程 | Q10；I2、I3；004「不做什麼」（組員 A 定、Owner 採用） |
| R5 | 點殖民者時，資訊面板把生理與心理分成兩區顯示，不合併成單一指標；佇列中的補給工作顯示要去的補給點（例如「前往水補給站」），玩家指派照 002 顯示格子 | `SYSTEM.md` SC2；訪談 Q2；I7 |
| R6 | `Hunger`、`Thirst`、`Relief`、`Stamina` 低於 30 時，殖民者**自己**產生一件優先度 3 的補給工作，排進自己的待辦佇列（沿用 002 的佇列與搶占）；同一條需求同時只有一件 | `VISION.md` §3.2；組內 2026-11-11；Q3、Q4 |
| R7 | 大廳有 4 個補給點：食物補給站、水補給站、廁所、休息區，各補一條需求。走到後待滿時間（休息區 60 秒，其餘 2 秒遊戲時間），該需求回到 100 | I1；Q5、Q6、Q11 |
| R8 | 任一條生理需求到 0、`Stress` 到 100 或 `Mood` 到 0 時進入 `Incapacitated`：不移動、不接新指派、不列在指派子選單，手上與佇列裡的指派全部取消。失能不會恢復 | `SYSTEM.md` `Incapacitated`；訪談 Q8；Q7–Q9 |
| R9 | 失能中生理照常下降；`Hunger` 與 `Thirst` 都到 0 時死亡：從 `Colony` 移除、從地圖消失 | `SYSTEM.md` SC1；訪談 Q8；Q9；I6 |
| R10 | 失能的殖民者在地圖上換顏色，面板標「失能」 | I5 |
| R11 | 需求、補給、失能、死亡都是純邏輯，不繼承 `Node` | `SYSTEM.md` S1 |

### 不做什麼

- 補需求的真正設施與建造 —— 「建造與自動化」feature 會把補給點換成設施；狀態差使工作變慢或產出下降 —— 002 的工作還只是佔位；「殖民者崩潰」的失敗判定（`VISION.md` §7）與結算畫面上的殖民者數據（`SYSTEM.md` S2、SC5）—— 本 feature 只提供「誰失能、誰死了」可以查詢；`BodyTemp` 的區域與事件旗標（SC7）—— 本 feature 沒有區域與事件，體溫維持初始值不變；救治失能者、醫療、收編新殖民者的事件；除了「失能者不能被指派」之外，不改 001、002 已驗收的行為

## Plan

### 方案

- **純邏輯**：`Physiology`（五條）與 `Psychology`（兩條）是兩個 class，資料層就不合併（SC2）。速率由「幾天走完全程」換算，天長沿用 `DayClock.SECONDS_PER_DAY`。`Stamina` 與 `Stress` 都只看呼叫端傳入的「是否在工作」：有工作（含建造、去補給、在食物／水／廁所待著）時 `Stamina` 降、`Stress` 升；在休息區休息或沒事時 `Stamina` 不變、`Stress` 降。`Colonist` 帶這兩個物件與 `incapacitated`。新增 `ColonistCare` 每幀依序推進：需求依這一幀開始時在做什麼變化 → 判定失能、死亡 → 走路與工作 → 做完的補給補滿 → 低於 30 經 `AssignmentBoard` 建補給工作（先補滿再檢查，才不會重複建立）。補給工作沿用 `Assignment`，多 `need` 欄位（玩家指派為空）與工作秒數（預設 2，休息區 60；`Wanderer` 改讀它），佇列與搶占全沿用 002。`Wanderer.advance()` 改為回傳這次做完的工作，用來分辨「做完」與「被取消」。
- **失能**：取消全部指派、從 `AssignmentBoard` 註銷，建立指派就會失敗、子選單也不列，不必改 002 的選單。**死亡**：`Colony.remove_colonist()`，`main.gd` 移除圓點、關閉選單，面板正顯示他時一併關閉。**補給點**：`SupplyPoints` 固定在大廳中線左、中、右約 `(14,15)`、`(28,15)`、`(42,15)`，休息區在中上約 `(28,8)`，測試確認是地板。**畫面**：地圖在補給點標「食／水／廁／休」；失能者圓點換灰色；資訊面板名字下加「生理」「心理」兩區與「失能」標示，佇列中的補給工作顯示名稱（I7）。沒採用：七條放同一個 `Needs` class（違反 SC2）；補給另開一套佇列（會和 002 的搶占打架）。已知行為：玩家在面板取消補給工作，下一次推進會再產生（需求仍低於 30）；「下一天」鈕只跳日期、不推進需求，和 001 殖民者的移動一致；在休息區待到一半被急件打斷要重新待滿 60 秒（沿用 002 的計時歸零）；選單開著時有人失能，要重開選單才更新（選了也只是指派失敗）。**與 004 整合**：merge `main` 後解衝突；`Construction` 加 `reserve_cells()`，`main.gd` 把補給點格子交給它，放置判定視為佔用；`main.gd` 每幀先 `care.advance()`（含走路）再 `construction.advance()`、`assign_builders()`，殖民者只推進一次。
