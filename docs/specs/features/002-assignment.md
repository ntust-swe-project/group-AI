# 002 — 指派與優先度

## Spec

### 這個 feature 要解決什麼

001 的殖民者只會閒晃。本 feature 讓玩家**下指令、定優先順序**：右鍵點一格打開指派選單，選誰去做、多急。每個殖民者有自己的待辦佇列，照優先度做事；比手上的事更急的指派**當下插隊**（SC4）。指派內容先只有佔位用的「工作點」（走到那格、待一下），真正的工作（建造、修理、吃喝）留給之後的 feature 接。

玩家感受到的：下了指令，殖民者立刻有反應；急的事先做。

| R8 | 點殖民者時，資訊面板列出他手上的事與佇列（優先度、格子），地圖上也標出這些格子；沒選人時地圖不畫標記 | 訪談 Q5（看得到有在動）；I5、I7 |
| R9 | 指派、佇列、搶占都是純邏輯，不繼承 `Node` | `SYSTEM.md` S1 |

### 不做什麼

- 真正的工作內容（建造、修理、吃喝、搬運）與需求數值 —— 之後的 feature
- 地圖上的指派標記與連線（I2 不納入：工作一多會擋視野）
- 一次指派給多人、框選、全站指派清單畫面、修改已下的指派（只能取消後重下）
- 右鍵選單的其他功能（Q7 說之後可能加，本 feature 只有指派）；鏡頭移動；改 001 已驗收的行為

## Plan

### 方案

- **純邏輯**：`Assignment`（id、格子、優先度）。`TaskQueue`（每個殖民者一個）：手上的事＋佇列，`add()` 時若比手上的急就搶占（手上的放回佇列）並立即回報「目標變了」，`cancel()`、`complete()` 取下一件。`Wanderer` 擴充：有任務時走向任務格、到了計時 2 秒、完成時通知；沒任務時照舊閒晃。`AssignmentBoard` 管全站指派與 id，負責建立（含可達性檢查，R6）與取消。
- **A1 的做法**：搶占在 `add()` 那次呼叫內直接讓 `Wanderer` 重算路徑，不等下一幀。
- **畫面**：`main.gd` 的 `_unhandled_input` 收右鍵，格子是可達地板才開 `AssignMenu`（新場景：殖民者 `OptionButton`、優先度 `OptionButton` 1–5、執行、該格現有指派與取消）。資訊面板加一個佇列清單。左鍵點人看名字不變。
